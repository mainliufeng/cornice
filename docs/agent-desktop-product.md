# Desktop and Pi execution contract

Human and each Agent have ten workspace slots, numbered 1–10 in their own UI. Agent workspaces have names scoped to a desktop identity; human numeric workspaces remain untouched. Each Agent runs Cornice on its preferred Wayland seat and output, including a real bar, menus and prompt surface. Captures include its shell. Human surfaces never enter Agent captures or pointer hit tests.

The bar uses two compact icons: a desktop selector and a control/status menu. Hover opens a popup, crossing from the icon into the popup keeps it open; click opens the popup too. The fullscreen viewer uses the same bar layout, workspace state and actions. Selecting a desktop is read-only. Control menu actions explicitly grant human takeover, end takeover, run/pause Agent, submit a task, or cancel a task.

Super+A opens the task prompt for the selected Agent. A task is attached to one compositor instance and desktop lifecycle. Starting a task does not seize a desktop being operated by a human. Only explicit run/resume or submission of a new task grants Agent input. A repeated submission checks the existing job lock before changing control. Cancel stops Pi and releases held input. One task per desktop runs at a time; repeated starts cannot replace an existing task silently.

Pi is the default executor. Endpoint, model, API mode and token source are configurable independently of desktop UI config; token material is private and omitted from status/logs/arguments. Local default uses the existing authenticated gateway's explicit DeepSeek deepseek-flash route. Built-in shell/file/network tools and unrelated Pi extensions/MCP/context files are disabled. Model tools are scoped to this desktop: state, screenshot, bounded input, workspace/focus/application launch, wait and finish. No raw CDP or human desktop fallback.

Human takeover, pause and full session locks immediately revoke old input grants. Human-only lock pauses by default; an already-authorized continue-policy job can continue while human surfaces remain hidden. The task can still read its control state (not protected pixels). Pi receives the changed control state and chooses wait or abort according to task context. Waiting never resumes the desktop. After explicit user resume, the executor checks the original lifecycle, acquires a new control binding, takes a fresh screenshot and re-evaluates the changed screen; old queued input is discarded. Retired desktops or dead compositor sessions terminate the task. UI shows execution state separately from seat control state.

Verification must exercise actual bars and 1–10 workspace switching, a real model performing UI actions, human takeover and text edits during a model run, wait/resume with fresh input, context-driven abort, lock/revocation, cancellation, and fresh installed artifacts. Real model/network errors are reported, never replaced by simulated model responses. Native physical-session verification is separate from isolated integration testing.

## Configuration and operation

The private default is `$XDG_CONFIG_HOME/cornice/agent-model.json` (override with `CORNICE_AGENT_CONFIG`). Configure with `cornice-agent-runtime configure` reading a JSON object on stdin: `endpoint`, `model`, optional `api` (default `openai-completions`), `pi` executable, and exactly one token source (`token`, `tokenFile` or `tokenEnv`). Files are written mode 0600. `config-status` deliberately omits credentials. An existing Pi installation is required; extensions use its public extension API. This machine uses `deepseek/deepseek-flash` at the existing local model gateway, with no automatic provider fallback.

Hover the monitor/Agent icon to select a desktop. Selection observes it without taking control. Hover the state icon to take over, end takeover, run/pause, start a task or cancel. Super+A opens the task prompt; Ctrl+Enter submits, Escape closes. Submission cannot replace a running task or take control from a human. End takeover leaves the Agent paused; choose Run Agent explicitly to let a waiting task continue. Job state is shown separately in the state menu. Private job records live under `$XDG_RUNTIME_DIR/cornice/<instance>/jobs/<desktop>`; they contain prompts/screenshots in tool history and must be treated as private.

Agent shell processes have separate Wayland seats and short per-instance IPC paths; lock/idle/polkit/notification ownership stays with the human shell. Each Agent has its own persistent browser profile and stable logical name. The executor and UI do not provide an OS security boundary against an application launched on a desktop. Physical session checks remain a separate rollout step; a prepared immutable candidate takes effect on next login, never by replacing the compositor under a running session.
